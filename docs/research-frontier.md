# Research Frontier

Press **Research** in the main Atlas toolbar and choose **Build session brief**. The existing Atlas canvas opens the research board. A colored ring identifies each hypothesis at any zoom level. Amber marks the top two directions in the current brief, teal marks promising directions, and violet marks directions that need more work. Hypotheses use the Atlas mind map's own drag and force layout, with links to cited concepts, claims, and parent hypotheses. Experimental positions are saved on the current device. Use **Fit hypotheses** to frame them, or choose a hypothesis from the list to focus its neighborhood. Ideas without a visible evidence or parent anchor stay in the list. **Branch from here** uses one bounded follow-up to look for a new direction and links a resulting hypothesis to its parent on the same map. **Archive** removes it from the board and **Restore** brings it back. Older published directions remain available on the board until archived. Subsequent sessions open the saved brief immediately. **Start research session** checks the current evidence against that brief and reuses it with zero model calls when the goal and evidence are unchanged. **Refresh brief** deliberately runs discovery again. For a changed source, the next session keeps eligible assessments from unaffected neighborhoods and rechecks a bounded set of affected hypotheses. A brief can contain fewer than three directions when too few pass critique.

**Add to Atlas** explicitly saves a main-Atlas concept labelled as a research hypothesis, with its starting point, uncertainty and provenance. It uses the first available subject from linked evidence and leaves the proposition list empty. **Promote to trail** is available for recording the approach in an existing investigation.

A direction shows the hypothesis, mathematical starting point, intuition, obstacles, possible novelty relative to the supplied records, and an actionable next question. Evidence opens the saved source text and available Atlas, conversation, trail, or original citation. **Deepen** performs a focused assessment with an expanded local packet. If the library has changed, start a fresh session to bring the brief up to date. **Promote to trail** adds an approach branch to a chosen existing trail. The branch cites its discovery run and evidence. Retrying promotion reuses its branch ID.

## Evidence and execution

- The server reads Atlas concepts and relationships, canonical propositions and joint arguments, integrated lesson records, working lesson maps and derivation targets, submitted derivation text, trail history, reviewed P1 evidence, and cited research findings from linked discussions. It reuses Atlas search for a supplied goal and follows stable IDs for adjacency. Layout and UI state are outside the fingerprint. Canonical appends from an interrupted lesson approval stay hidden until integration finishes.
- The deterministic planner prioritizes known gaps and unresolved research, links topics across lessons by explicit concept bindings, and includes a separate exploration packet when other evidence is available. Large records are omitted whole. A joint argument travels with its conclusion and every premise. Prompts distinguish canonical statements, reviewed derivations, lesson depictions, and tentative model readings.
- A fresh pass typically uses two generation calls of up to nine candidates each, then one structured critique call. Changes to a small portion of the frontier can use one generation call. Deterministic filtering removes whitespace-equivalent hypotheses while preserving mathematical symbols and case. Critique reviews semantic overlap, and deterministic selection favors distinct principal sources among the final directions. Usefulness and support carry more weight than surprise. If the leading opportunity has additional nearby evidence and budget headroom, it receives a fourth call. Manual deepening uses one call.
- The 27,000-token working target informs shortlist size. The configurable budget target starts at 35,000 and governs optional deepening. Prompt and retrieval packets have character bounds and each request carries an output target. Provider-specific accounting and reasoning can differ, so these are estimates. The job stores reported input, output, cache reads and writes, and completed model steps using the existing usage accounting.
- Choose the Researcher model and thinking level under **Settings → Agent → Models**. The Researcher row applies to Frontier and research jobs and inherits the Cheap slot by default. The configured model is used through Pi, the shared background semaphore, and provider consent gates. Each stage receives fresh context and a submit-only schema. The desktop can show the provider before dispatch. Bounded source packets and selected research history leave the device when the configured provider is remote.

## Persistence and recovery

The ledger is stored in ordinary versioned Frontier job records under the application data root. It retains source fingerprints, evidence, candidates, assessments, earlier rejections, and completed stage checkpoints. One pass runs per profile. Job events update the brief after durable writes. After interruption, **Resume** continues from the saved stage and uses the pinned model. **Retry from saved progress** does the same after a recoverable stage failure. A crash between a provider response and its checkpoint may repeat that call and its reporting can be incomplete. **Cancel** uses the shared job abort registry and leaves the last successful brief available.

An exact title match or a conceptual connection establishes no mathematical identity. An explicit promotion writes a research branch through existing trail validation and receipts. Canonical writes require the normal reviewed integration path.

## Adaptive auto-discovery

Choose **Auto-discovery** in Frontier. **Single pass** still opens its own saved brief and reuses unchanged evidence with zero calls. An auto-discovery run starts with one broad batch of up to six candidates and a dedicated critique call, then plans smaller actions against a cumulative portfolio. **Discovery settings** defaults to a 50,000-token session target, six follow-up iterations, two consecutive low-gain iterations, a minimum gain of two portfolio points, and minimum action priority 0.8. The progress view shows the chosen action, estimated cost, reported usage, outcomes, and stop reason.

- The policy examines a bounded snapshot of graph neighborhoods and exact evidence, including required premises. It can explore an uncovered neighborhood, develop an alternative mechanism, reformulate a specific rejection, combine adjacent complementary hypotheses, challenge an uncertain assumption, or deepen a promising direction. Earlier critique provides mechanism labels, failure mechanisms, unresolved assumptions, alternatives, and missing evidence. The targeted stage packs a compact summary from the relevant parents and recent attempts.
- Action priority is integer-weighted research value divided by estimated thousands of tokens. New evidence and unresolved assumptions increase the value of investigation. Overlapping neighborhoods and previously attempted mechanisms reduce it. The first affordable eligible uncovered neighborhood gets a slot, so the controller can defer broader exploration until after the initial critique. This is a coverage and information-gain heuristic with no calibrated probabilities. The pure action selector in `frontier-plan.ts` is the policy seam.
- Each follow-up uses one submit-only call and returns at most one already assessed idea and can reassess a targeted parent. The brief ranks actionable hypotheses by usefulness, support, and evidence-relative novelty. Exact duplicate questions and repeated mechanism labels on the same principal source are filtered. A weaker reassessment leaves the earlier assessment available. An automatic challenge can remove a hypothesis from the portfolio when it rejects the mechanism and cites additional evidence. Outcomes and lineage remain in the ledger. A gain is the change in the sum of the selected portfolio's scores. These are internal decision signals and do not measure mathematical truth or research usefulness.
- The controller budgets every new call in adaptive mode using accumulated reported usage including cached tokens, estimated serialized input and output, and a reserve for the broad critique. The next dispatch must fit the remaining estimate. Output limits are requested per call where supported. Missing provider usage is tracked separately as an estimate. Providers may count tokens differently, so actual usage can exceed the target. A completed result is retained if a call reports more tokens than expected.
- The versioned job record snapshots a bounded neighborhood pool, action choice, context IDs, prior attempt lineage, outcome, and measured or estimated spend. Resume uses the same evidence and skips completed stages. A response lost before the result checkpoint can be replayed if the remaining budget allows it. Cancellation keeps the previous completed brief and the interrupted job record. The next session can pick up changes to the Atlas sources.
- **Interested** increases follow-up priority. **Dismiss** excludes the exact hypothesis from the next adaptive portfolio and its follow-up actions. **Revisit later** pauses targeted follow-up for 24 hours. Feedback is stored on completed job records and informs future runs. The displayed brief stays available while you give feedback.

### Adaptive benchmark

Run `NODE_ENV=test node --import tsx scripts/benchmark-research-frontier.ts` to compare single pass, naive repeated broad passes, and adaptive auto-discovery. Each variant uses the same 50,000-token dispatch target and the same pre-outcome evidence for each of the three archived cases. The naive baseline reruns the same broad pipeline and keeps the strongest exact-ID assessments across passes. Use `--context` for the older four-way evidence ablation.

The JSON reports recorded usage, estimated unreported usage, distinct principal sources, mechanism labels where available, exact duplicate IDs, score changes after the first brief, and tokens per model-rated worthwhile direction. In scripted mode the model supplies fixed outcomes, so budget accounting and convergence are the checks of interest. For an opt-in provider run, add `--live`. Give reviewers only `blindBriefs`; keep the variant mapping in `results` until scoring is complete. Rate each direction for a precise mathematical starting point, a plausible mechanism, a decisive next action and redundant content. Compare reported tokens per independently rated worthwhile direction. This run uses the configured Researcher model and may incur charges.
